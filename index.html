🧩 plugin-hub - Connect Plugins Without Writing Any Code

plugin-hub is a self-hosted program for Windows that lets you attach small add-on modules ("plugins") to one central hub, then chain them together into automated sequences that do work for you. Everything runs on your own computer. There is no account to create, no subscription, and no cloud service in the middle.

Instead of juggling a dozen separate tools, you open one window, pick which plugins should talk to each other, and describe the order you want them to run in. plugin-hub handles the rest: it checks that each plugin is allowed to do what it claims, keeps track of what is installed, passes messages between them, and records what happened so you can look back later.

🚀 What Is plugin-hub?

Think of plugin-hub as a power strip for software. A power strip does not do any work by itself, but it gives every device a safe, standard place to plug in. plugin-hub does the same thing for plugins: every add-on connects through the same socket, follows the same rules, and can be swapped out or upgraded without disturbing the others.

Under the hood, plugin-hub is written in the Rust programming language, which is known for producing fast, stable software that does not crash easily. Each plugin runs in its own separate process — meaning if one plugin misbehaves, it cannot take down the whole program. The hub simply notices the problem, restarts or removes that plugin, and keeps everything else running.

The program is built around five ideas that appear throughout the interface:

  • Contracts — a written agreement about what each plugin is allowed to send and receive, so mismatched add-ons are refused before they cause trouble.
  • Discovery — the hub automatically finds plugins that are available on your machine and lists them for you, so nothing has to be typed in by hand.
  • Orchestration — you arrange plugins into a sequence with dependencies, and the hub works out the correct running order for you.
  • Event bus — a shared message line that lets plugins announce "this happened" so other plugins can react immediately.
  • MCP tool surface — a standard, well-documented way for outside assistants and automation tools to request work from your plugins.

✨ What You Can Do With It

You do not need to understand any of the above to get value from plugin-hub. Here is what those capabilities look like from a normal user's point of view.

  • Build a routine once, run it forever. Chain three or four plugins into a single sequence and start the whole chain with one click.
  • Add or remove pieces safely. A plugin can be disabled or upgraded without breaking the routines that use it.
  • See what happened. A readable activity log shows each step, when it ran, and whether it succeeded.
  • React automatically. When one plugin finishes something, the hub can instantly trigger another one — no manual step in between.
  • Keep everything local. Files, settings, and logs stay on your own computer in a folder you choose.
  • Let other apps ask for help. The built-in tool surface lets compatible assistants request actions from your plugins in a controlled way.
A quick word on jargon: if you see words like "DAG," "gRPC," or "MCP" in the project description, they describe how the plumbing works inside. You never need to type them anywhere. They exist so plugins from different authors can cooperate without you having to configure anything.

👥 Who This Is For

plugin-hub is aimed at people who run things on their own computer and want them to work together, but who do not want to write scripts. Typical users include:

  • Small teams who want one tidy place to run repetitive internal tasks.
  • People experimenting with AI assistants who want a safe, local way to give them extra abilities.
  • Anyone who prefers self-hosted software over handing data to an online service.
  • Tinkerers who like the idea of plugging modules together like building blocks.

3Download the Windows file.

🖥️ Your First Five Minutes

When the main window opens, you are looking at three areas: a list of plugins on the left, a large working area in the middle, and an activity panel at the bottom.

  1. Check the plugin list. Any plugins plugin-hub found on your computer will already be listed, with a small status dot beside each name. A green dot means it is ready. An amber dot means it is starting up. A red dot means it needs attention.
  2. Turn one on. Click a plugin name, then click Enable. The status dot should turn green within a few seconds.
  3. Look at the activity panel. Every action you take is written there in plain language, along with a timestamp. If something does not happen as expected, this panel is the first place to look.
  4. Create your first sequence. Click New Sequence, give it a name you recognise, then drag two enabled plugins into the working area. plugin-hub will draw a line between them showing which runs first.
  5. Run it. Press the play button. The steps light up one at a time as they complete, and a summary appears in the activity panel when the whole sequence finishes.

Nothing you do here is permanent. Sequences can be renamed, reordered, or deleted at any time, and disabling a plugin never deletes its settings.

🧰 Everyday Tasks

Adding a new plugin

Place the plugin's folder in the plugins directory that plugin-hub created during setup, then press the refresh button in the toolbar. The new entry appears in the list automatically — you do not need to restart the program.

Pausing a plugin

Select the plugin and click Disable. Any sequence that relies on it will show a warning until it is re-enabled, but the rest of the program keeps working normally.

Reviewing what ran

The activity panel keeps a rolling history. Use the search box above it to filter by plugin name or date. This is handy when a sequence did something unexpected three days ago and you want to know exactly what happened.

Moving to a new computer

Copy the whole plugin-hub working folder to the new machine, install the application there, and point it at the copied folder from the settings screen. Sequences, plugin settings, and history come along with it.

❓ Troubleshooting

The window does not appear after launching. Wait up to a minute on the very first run. If nothing happens, open Task Manager and check whether plugin-hub is listed. If it is, close it from there and launch it again.

A plugin shows a red dot. Click it and read the message underneath the name. The most common cause is that the plugin was built for a different version of the hub. Download the matching plugin version from the same releases page and try again.

A sequence stops halfway. Open the activity panel and look at the last line. It names the plugin that stopped and gives a short reason. Disable that plugin, run the sequence again, and confirm the other steps still complete.

Windows warns about the file. This is the standard warning shown for software that does not have a paid publisher certificate. Use More info then Run anyway, but only when you downloaded from the link on this page.

Your antivirus flags the download. Add the plugin-hub folder to your antivirus exclusions. Programs that start other programs — which is exactly what a plugin hub does — are sometimes treated cautiously by security software.

🔒 Privacy and Safety

plugin-hub is self-hosted, which means the program, the plugins, your configuration, and your logs all live on hardware you control. Nothing is uploaded to a project server, and there is no telemetry to switch off. Plugins run in separate processes with a contract that describes what they may do, so a plugin cannot quietly reach into another plugin's files or settings. If a plugin crashes, the hub isolates the failure and keeps the rest of the program running.

Because there is no central account, there is no password to recover and no online profile to manage. Your data stays in the working folder you chose during setup. To back everything up, copy that folder. To remove all traces, delete it.
